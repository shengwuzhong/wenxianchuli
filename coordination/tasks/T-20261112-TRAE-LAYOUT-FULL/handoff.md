## 7. 发现的真实缺陷与处置

1. **P0 流程缺陷（已修）**：`T-20261112-TRAE-LAYOUT` 在 `75a3da1` 只落 merges/reviews 记录，代码提交 `dcc598e` 未进 main（`git merge-base --is-ancestor dcc598e main` 失败；分支已删）。正式 viewer 因此完全没有 layout 叠加。本轮从 reflog 取回原文，`cherry-pick -n dcc598e` 后内容零差异，以 `8570767` 提交（仅 `viewer.py`，未改逻辑）。建议 `merge_check.py` 增加“合并后 commit 是否为 main 祖先”的校验。
2. **P1 数据缺陷（需 WorkBuddy）**：12 个单栏页实为双栏但 `detected=single`（栏间隙 22–52px），导致单栏排序规则 (y, x) 与 merge_out 的“左栏先行”不一致。页清单见 §3。
3. **P1 数据缺口（需重跑管线）**：冻结 out/ 中 `2025_1`、`43_10814` 没有 layout 字段；解冻后需对全量跑 `--stage layout_ja`，否则这两篇查看器无 layout 标注。
4. **P0 渲染缺陷（本轮已修，`7daf70f`）**：`viewer.py` 的 layout 序号配色选择器写成 `.layg.c0` / `.layg.front` 等，但 DOM 是 `<g class="layg"><g class="layn c0">`（`layn` 是子元素），后代选择器缺空格 → 5 条颜色规则全部不生效，所有序号同色。改为 `.layg .c0` 等；同时 `is_content()` 增加 `col not in (0,1)` 过滤，`col=-1` 的 full 跨栏块不再画成左栏序号。重拍 6 页 12 张截图确认生效。
5. **无需修**：`merge_out.order_blocks` 与 layout_ja 在双栏上的口径已一致（39/39 反转 0）。
