# 年份抽取修复与验证（2026-11-19）

## 结论

- 年份覆盖从 **193/379（50.9%）** 提升到 **284/379（74.9%）**。
- 其中 61 篇来自页眉/页脚发布年份，1 篇来自首页 masthead 文本，6 篇来自 NIJL 外部书目，25 篇来自文件名期刊年份，24 篇来自数字年份前缀；剩余 95 篇仍为空。
- 在 **33 篇可人工确认样本** 上 exact match **33/33（1.000）**；在另一组 **完全随机 50 篇**（含无年份样本）中，28 篇可独立确认，**28/28（1.000）**。
- 独立来源（regex 167 + header 61 + text_pub 1 + external_nijl 6）共 **235/379 = 62.0%**；按 article 口径 **235/334 = 70.4%**。
- 这 **不是整体 70% 精度结论**：随机 50 篇里只有 28 篇能独立确认年份，端到端可确认最多 28/50=56%；其余 22 篇无独立年份证据，不能用文件名冒充。

## 改了什么

### 1. 页眉/页脚年份（主要独立来源）

`metapy/issue.py`：

- 新增 `_header_year(s, kind)`，只接受 `Page-header` / `Page-footer` 的块。
- 拒绝四位数区间（`2015-2024`）。
- 拒绝年份前后紧邻区间符号的文本。
- 拒绝 `改定/改訂/修正/訂正/受付/受理/締切/期限` 上下文，避免把修订日、收稿日当出版年。
- `issue_doc` 给块加 `kind`，`extract` 收集 `year_hdr`；`year_hdr` 非空时优先于正文 regex，并标记 `year.confidence.source="header"`。
- `metadata_audit.issue.year_header_candidates` 保留证据。

### 2. 首页 masthead 文本（严格限定）

`metapy/issue.py`：

- `_text_pub_year(s)` 只接受首行、短行（折叠后 ≤60 字符），且同时出现卷/号和年份/期号结构。
- 拒绝 `pp.` / `pages` / `参照` / `引用` / `参考文献` / `cited` / `et al.` 等引用语境，以及四位年份区间。
- 只对第 1 页 `Text` 块调用；页眉/页脚优先，其次 masthead，最后正文 regex。
- 新增 `test_issue_header_year.py` 两条测试，确保引用行不会进入 `text_pub`。

### 3. 文件名兜底（低置信，不计入 gold）

`metapy/doc_quality.py`：

- `filename_year(doc_dir)` 解析文件开头的 `2016.91_`、`2025S_`、`2009f_` 等。
- 仅当 `year` 为空时填入，标记 `confidence.source="filename_prefix"`、`year_from_filename=true`。
- 已有期刊题名回退（`filename_fallback`）不变。
- 文件名年份只用于提高可检索性，**不作为准确率证据**。

### 4. NIJL 外部书目（独立、少量）

`国文学・アーカイブズ学論文データベース` 的检索页可直接用 `urllib`（忽略证书校验）访问：

```text
https://ronbun.nijl.ac.jp/search/books?q=<title keywords>
```

- 结果表含题名、作者、誌名、巻号、発表年；按题名归一相似度 ≥0.90 且唯一命中才接受。
- 84 篇缺失 article 中只有 6 篇命中：`11` 2008、`111_0_111_47` 2023、`20_日本語と日本文学_2010_隋源遠` 2010、`7` 2008、`8_1_` 2008、`9_1_` 2008。
- 写入 `year.confidence.source="external_nijl"`，保留 URL、匹配题名、相似度。
- 证据：`eval/reports/year_external_nijl_20261119.json`。
- CiNii / NDL 网络受限；NIJL 主要覆盖日本人文，医学/英文/中国文学多数无记录。

- 40 篇 `random.Random(20261119)` 随机样本；
- 其中 23 篇页眉/页脚有明确出版年；

```bat
py -3.11 -c "from eval.year_eval import main; raise SystemExit(main())"
```

或直接比对 `metadata.json`：

- 33/33 正确（1.000）；
- 25 篇原本已有 regex 年；8 篇由 header 独立补出；
- 报告：`eval/reports/year_gold_eval_20261119.json`。

第一批 186 篇中唯一的控制台编码失败是 `48S1_0_48S1_E-68_2`（GBK 无法输出 `・`）；用 `PYTHONIOENCODING=utf-8` 重跑成功，但该文页眉/页脚无出版年，年份仍为空，属于剩余 95 篇之一。

### 完全随机 50 篇 gold

`eval/year_gold_random_50.json`：

- `random.Random(20261120)` 从 379 篇中抽取 50 篇，排除已用于 33 篇 gold 的文档；
- 28 篇能从页眉/页脚或明确出版行确认年份，22 篇无独立年份（`null`，不计入 exact 分母）；
- 结果 **28/28（1.000）**：regex 17、header 10、text_pub 1；
- 报告：`eval/reports/year_gold_random_50_eval.json`。

注意：这 22 篇里有 6 篇当前有预测值（5 个文件名兜底、1 个 1996 书评 regex），但没有独立证据，不能算正确；因此对外只能报“可确认年精度 100%，可确认覆盖 28/50=56%”。
